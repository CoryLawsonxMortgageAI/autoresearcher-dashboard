## What the directive asks me to do

The directive frames itself as "PHASE 6 — Autopilot harness + ship" of a
larger autoresearcher system. As I read it, the operator (Cory) wants
the following, in roughly this order:

1. **Nightly SCOUT cron** on a worker box, scoped to the vertical
   allowlist in `/packages/skills/autoresearcher/verticals.json`.
   Findings land in an `opportunities` inbox and emit a Pusher event;
   if the dashboard is open, a toast surfaces in real time.
2. **Weekly digest email** to Cory via Resend or SendGrid (sent from
   Vercel) containing the top 10 new opportunities, scoring breakdown,
   recommended action, and signed-magic-link greenlight buttons.
3. **Vercel deploys** for `/apps/web` and `/services/api`, with
   GitHub→Vercel auto-deploy on `main` merge and Preview deploys for
   every PR matching `feat/*`.
4. **Worker** running on Railway / Fly / Hetzner, with
   `/scripts/sync-secrets.ts` pulling secrets from Vercel on boot.
5. **PlanetScale (or chosen MySQL)** database, with
   `drizzle-kit migrate` run from CI.
6. **Sentry** configured via DSN in Vercel envs; **OpenTelemetry**
   traces shipped to Honeycomb or Grafana Cloud (whichever the
   operator already has — file BLOCKER if neither).
7. **Reproducible bootstrap**: `pnpm bootstrap` from a fresh checkout
   should clone `.env` from Vercel, run migrations, seed eval
   fixtures, start the dev server, and open the browser to
   `/activity`.
8. **HISTORIAN write-up** at `/docs/runs/v1.0-launch.md`.

In addition the directive specifies operating rules I must obey from
the moment I start any work, not just during Phase 6:

- A three-tier merge policy. Tier-1 paths can auto-merge only after
  Cory commits a GPG-signed `/.automerge-authorized` file, sets the
  Vercel env `AUTOMERGE_AUTHORIZED=true`, and 24h has elapsed. The
  agent must NEVER create that file or set that env var.
- Tier-3 paths (`auth/`, destructive migrations, `.github/workflows/`,
  `vercel.json`, secret rotation, `/legal/**`) are always blocked
  from auto-anything; only "open in GitHub" links are surfaced.
- Mandatory revert path (revert-merge + down-migration + Vercel
  rollback) must exist BEFORE Tier-1 auto-merge is enabled.
- Rate ceiling: max 5 Tier-1 auto-merges per hour, 20 per day.
- A long list of `.claude/hooks.json` PreToolUse / PostToolUse hooks
  blocking destructive commands and unsafe writes.
- Stop conditions including "material ambiguity in this directive",
  per-run cost > $10, cumulative cost > $100, missing required
  Vercel env var, opportunity outside allowlist, Tier-3 auto-merge
  attempt, Pusher channel down >60s, etc. Each must produce a
  `BLOCKER-<phase>-<ts>.md` with failing command/output, diagnosis,
  three ranked options, and a default-after-24h action.
- Operating cadence: overwrite `/docs/runs/_inflight.md` every 60
  minutes; HISTORIAN writes `/docs/runs/phase-N.md` at each phase
  completion; emit `phase_completed` / `blocker_filed` events.

The directive's own first-action instructions are:
1. Write `/docs/adr/0000-meta.md` summarizing my understanding (this
   file). If material discrepancy with the directive, file BLOCKER
   before doing anything else.
2. Write `/docs/adr/0000-repo-state.md` and
   `/docs/adr/0001-additive-plan.md`, then run `vercel env ls`, then
   begin Phase 0.

## Discrepancies I see vs. directive intent

I have written this summary as faithfully as I can. My summary
matches the directive's letter. The discrepancy is not between this
summary and the directive — it is between the directive and the
**actual repository state**. That is a material ambiguity, and I am
filing the BLOCKER as the directive itself instructs. See
`docs/adr/0001-repo-state.md` and `BLOCKER-phase-6-2026-05-09.md`.

## Numbering note

The directive specifies BOTH `0000-meta.md` AND `0000-repo-state.md`.

file and shifted the others to `0001-repo-state.md` and
